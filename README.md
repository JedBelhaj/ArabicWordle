# ArabicWordle

A Wordle clone with real Arabic and English dictionaries, single-player and a live multiplayer mode (rounds, scoring, chat) built on React + Socket.IO.

## Features

- **Single-player** — pick Arabic or English and a word length (3/4/5 letters), guess against a real dictionary word, RTL layout for Arabic, on-screen + physical keyboard input.
- **Multiplayer** — create or join a room, host configures word length/tries/rounds/time limit/language/scoring, everyone plays simultaneous rounds with a live progress sidebar, in-room chat, and a running scoreboard across rounds. Round outcomes are computed server-side so the answer is never exposed to clients before it's revealed.

## Project structure

- `src/` — Vite + React frontend
- `backend/` — Express + Socket.IO server (in-memory room/session store, no DB)
- `shared/wordbanks/` — precomputed Arabic/English word lists, grouped by length, generated by `scripts/build-wordbanks.js` from `src/assets/arabic_words_5_letters.txt` and the `word-list` npm package

## Setup

Requires Node 20+.

```bash
# frontend
npm install
cp .env.example .env   # VITE_SOCKET_URL, defaults to http://localhost:8000

# backend
cd backend
npm install
cp .env.example .env   # PORT and CORS_ORIGIN, defaults are dev-friendly
```

## Running locally

Two terminals:

```bash
# terminal 1 — backend
cd backend
npm run dev

# terminal 2 — frontend
npm run dev
```

Open the printed Vite URL (typically http://localhost:5173). `/singleplayer` works with no backend running at all; `/` and `/multiplayer/:roomId` need the backend for room/session sockets.

## Regenerating the word banks

Only needed if you change the source word list:

```bash
node scripts/build-wordbanks.js
```

## Deploying

The frontend reads `VITE_SOCKET_URL` and the backend reads `PORT`/`CORS_ORIGIN` from the environment, so pointing them at a deployed backend URL is just an env var change — e.g. a static host (Vercel/Netlify) for the frontend and a small Node host (Render/Fly.io/Railway) for `backend/`.
